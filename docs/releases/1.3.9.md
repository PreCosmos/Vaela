# Full-screen windows are left alone

Vaela now stays out of the way of full-screen windows such as games and video players.

- Mouse gestures and the right-button radial menu no longer act on a full-screen
  window. Its right button goes straight to the application, as it does for
  apps in `RightButtonApps`.
- The coral handles of the layout switch and the workspace bar are hidden on a
  monitor whose topmost window is full screen, and come back when it leaves
  full screen, is minimized or is covered by another window. Other monitors are
  not affected.
- Keyboard shortcuts, including the radial menu's (Meta+Ctrl+M), still work.

Install on Arch Linux / CachyOS:

```bash
curl -fLO https://github.com/PreCosmos/Vaela/releases/download/v1.3.9/vaela-desktop-1.3.9-1-x86_64.pkg.tar.zst
sudo pacman -U ./vaela-desktop-1.3.9-1-x86_64.pkg.tar.zst
```

Log out and back in to load the new KWin plugin. Installation does not restart
your session.

This remains an Arch preview. The release build runs the five CTest suites before
publishing; the compositor session test, which now covers full-screen windows,
was not run for this release, so live desktop verification is still needed. The
workspace-bar pointer activation and native window-resize integration failures
reported in 1.3.7 are unchanged. No Fedora RPM is included.

The binary pins the upstream KWin version it was built against; inspect the
package dependencies with `pacman -Qip` and rebuild if your KWin version differs.
The release includes the source archive, generated PKGBUILD and SHA256SUMS.
